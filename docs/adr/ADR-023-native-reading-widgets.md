# ADR-023 — Bubo widgets on Android and iOS

> **2026-10-01:** the widget set and visuals were redesigned by
> [ADR-026](ADR-026-streak-widget-scenes.md). Privacy, expiry and publishing below still apply.

- Status: Accepted
- Date: 2026-10-01

## Context

The owner requested native widgets while continuing Task 09, using the existing visual language
and official assets. Backlog items 29–33 describe reading, weekly rhythm, a complete summary,
mascot states and compact lock screen widgets. Expo Go cannot load this local native module.

## Decision

- Use a local Expo module (`apps/mobile/modules/bubo-widgets`), Android AppWidgetProvider /
  RemoteViews, and a SwiftUI WidgetKit extension. No widget service, AI provider, analytics,
  extra backend route or database migration is needed. `expo-modules-core` is now declared
  directly at the exact installed SDK version (57.0.19); it was already provided by Expo.
- Three Android home widgets: **Continuar leitura**, **Ritmo da semana**, **Bubo completo**,
  resizable, with a system pin request when the launcher supports it. iOS reading/rhythm support
  small, medium and large; complete supports medium/large and circular/rectangular/inline
  lock screen families. Android lock screen availability belongs to the OS/launcher; this
  implementation registers home widgets and does not promise Android keyguard support.
- Native resources are generated by `with-bubo-widgets.config.cjs` at prebuild: canonical PNGs
  and Plus Jakarta Sans fonts are copied byte for byte. Colours come from `src/theme/colors.ts`,
  including dark tokens, instead of a separate native palette. Widgets follow the system theme.
  The Android native UI uses a rounded card, a bordered purple button and progress; SwiftUI uses
  the same tokens with system widget margins. No mascot is generated, recoloured or traced.
- The shared Zod `widgetSnapshotSchema` accepts only book title/page/progress, safe navigation
  links, reading-day activity, weekly goal and review counts. No session cookie, API credential,
  e-mail, reflection, recall answer or community text goes to the extension. Android uses private
  SharedPreferences and a private cached cover; iOS uses App Group
  `group.com.joaoaraujo.bubo.widgets`. App and extension entitlements and EAS extension metadata
  are configured together. The extension ID is `com.joaoaraujo.bubo.widgets`.
- Existing TanStack queries provide account-scoped data. A root observer publishes after shelf,
  session and review invalidations, when coming back to the foreground, and when the calendar
  date or device widget settings change. `weekReadingDates` is added to `/v1/me/stats`: **only
  reading_sessions** count toward the widget's reading rhythm; review-only days do not.
  The existing cognitive-week field keeps its contract. Query cache moves to v6.
- The weekly widget goal is a **device preference**, explicitly adjustable 1–7 days (default 4).
  It is a target, never invented activity. Widgets can be disabled on this device; lock screen
  title is hidden by default. An explicit choice can show the title on iOS, with
  `privacySensitive()` still respecting system redaction. The cover never appears on lock widgets.
- The snapshot uses the most recently updated `reading` shelf entry. Unknown page totals omit
  percentage; an empty shelf shows a real empty state. A missing/unavailable cover omits the
  image and keeps the title. Review counts use **offered cards after the daily cap**, with
  the next future review date shown when available. Links open guarded book/session/Hoje/Revisar
  routes; widgets never mutate reading records or invent XP.
- Snapshot temporal claims expire at local midnight or 24 hours after the **oldest** query
  response, whichever comes first. Reopening offline does not extend expiry. After expiry the
  native view hides book and counts and asks to open Bubo; no unauthenticated background API
  access. Android has a system-controlled 30-minute update interval; WidgetKit supplies entries
  for 06:00, 22:00 and expiry. Systems can delay refresh; these are not real-time guarantees.
- Publication is serialized. A generation counter invalidates old cover downloads on newer
  data, disabling widgets, account changes, sign-out, revocation and deletion. Native clear
  removes snapshot and cached cover and refreshes installed widgets.
- Pose mapping: **reading** for a current book; **review** for offered reviews; **celebrating**
  when the weekly reading goal is reached; **empty** after today's reading with no offered cards;
  **sleeping** at 22:00–05:59; **welcome** for an empty/no-session widget; **neutral** for an
  out-of-date calendar response. These are existing official poses, not new artwork.

## Validation and boundaries

Domain tests cover empty data, reading-only days, duplicate/future dates, page/goal caps,
review limits, official pose selection and local expiry. Publisher tests cover sign-out during
cover download, switching accounts, ordering and native/network failures. Native-generation
tests check asset/font hashes, light/dark tokens, entitlements, one embedded extension,
source/resource membership, host signing/version and idempotent target generation.

Android prebuild, both-platform autolinking, and Android/iOS JavaScript exports are checked locally.
The iOS project/mods are generated and inspected locally with Expo's configuration pipeline
(the public prebuild command skips iOS on Windows). **This is not native compilation.**
An APK build requires Java and Android SDK; Swift compilation and iOS device validation require
macOS/Xcode or an authorized EAS build and Apple signing. Device acceptance of layout, large
fonts, VoiceOver/TalkBack, launcher resize/pin, background refresh and deep links remains pending.

Live Activities / an Android ongoing session notification (backlog 34) are a separate slice and
are not implemented by these widgets. Retention curves / Bubo Score remain Task 06, with a model
required first. Push configuration remains the owner's Task 09 dependency.
